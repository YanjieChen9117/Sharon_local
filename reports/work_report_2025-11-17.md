# NY Taxi Trip Data Work Report
**Date:** November 17, 2025

## Overview

This report documents the optimization of the NYC taxi trip data processing pipeline. The key improvements include:

1. **Weather Data Alignment**: Integrated weather data that is aligned with other team members' datasets
2. **Spatial Aggregation Optimization**: Switched from trip-based aggregation to zone-based aggregation, providing a more comprehensive view of traffic patterns at the NTA (Neighborhood Tabulation Area) level
3. **NTA-Level Weather Data**: Replaced the uniform Central Park weather data with NTA-specific weather data, enabling more accurate spatial analysis

## Work Details

### 1. Weather Feature Workflow Script (`weather_feature_workflow.py`)

#### Purpose
Created a comprehensive workflow script to generate NTA-level weather data for all relevant zones, replacing the previous approach that used uniform Central Park weather data for all regions.

#### Data Sources
- **NTA Lookup File**: `documents/NTA_lookup.md` - Contains the list of NTA codes to be processed
- **NTA Geographic Data**: `data/2020_Neighborhood_Tabulation_Areas_(NTAs)_20251115.csv` - Contains geometric data (MULTIPOLYGON) for each NTA zone
- **Weather API**: Open-Meteo Archive API (`https://archive-api.open-meteo.com/v1/archive`) - Provides historical hourly weather data

#### Implementation Details

The script follows a four-step workflow:

1. **NTA List Extraction**
   - Reads NTA codes from the lookup markdown file
   - Parses the file format (e.g., `MN0191 - 12, 104`) to extract zone codes
   - Filters out comments and empty lines

2. **Centroid Calculation**
   - Loads NTA geometric data from CSV file
   - Parses MULTIPOLYGON strings to extract coordinate points
   - Calculates centroid coordinates (latitude, longitude) for each NTA zone by averaging all coordinate points
   - Maps each NTA code to its centroid location

3. **Weather Data Retrieval**
   - For each NTA zone, fetches hourly weather data from Open-Meteo API using the zone's centroid coordinates
   - Retrieves the following weather variables:
     - `temperature_2m`: Temperature at 2 meters above ground (°F)
     - `precipitation`: Precipitation amount (mm)
     - `wind_speed_10m`: Wind speed at 10 meters above ground (mph)
     - `relative_humidity_2m`: Relative humidity at 2 meters (%)
   - Date range: January 1, 2023 to October 15, 2025
   - Data resolution: Hourly
   - Timezone: America/New_York
   - Includes rate limiting (0.5 second delay between API calls) to avoid throttling

4. **Data Consolidation and Storage**
   - Merges weather data from all NTA zones
   - Standardizes datetime format (removes timezone info)
   - Organizes columns: `datetime`, `nta_code`, `nta_name`, `temperature`, `precipitation`, `windspeed`, `humidity`
   - Saves to CSV file

#### Key Features

- **Spatial Accuracy**: Each NTA zone now has its own weather data based on its geographic centroid, rather than using a single Central Park location
- **Comprehensive Coverage**: Processes all NTA zones defined in the lookup file
- **Error Handling**: Includes robust error handling for missing files, API failures, and data parsing issues
- **Progress Tracking**: Provides detailed progress logs for each step

#### Output File
- **Location**: `data/nta_weather_data.csv`
- **Format**: CSV with hourly records
- **Structure**: Each row represents one hour of weather data for one NTA zone
- **Columns**: `datetime`, `nta_code`, `nta_name`, `temperature`, `precipitation`, `windspeed`, `humidity`

### 2. NTA Zone-Based Hourly Taxi Data Processing Script (`process_nta_hourly_taxi_data_zone.py`)

#### Purpose
Created a new data processing script that aggregates taxi trip data by hour and NTA zone, providing both inflow and outflow features for each zone. This represents a significant shift from the previous trip-based aggregation approach.

#### Data Sources
- **Yellow Taxi Data**: `yellow_tripdata_*.parquet` files (monthly parquet files)
- **Green Taxi Data**: `green_tripdata_*.parquet` files (monthly parquet files)
- **NTA Weather Data**: `data/nta_weather_data.csv` (generated by `weather_feature_workflow.py`)

#### Workflow

The script processes data through the following steps:

1. **Data Loading and Merging**
   - Automatically detects all available monthly parquet files (both Yellow and Green taxi)
   - Loads and merges Yellow and Green taxi data for each month
   - Normalizes field names (handles `tpep_` vs `lpep_` prefixes)

2. **Data Cleaning**
   - Validates pickup datetime matches the file's month
   - Filters out invalid records:
     - Trip distance: 0 < distance < 100 miles
     - Fare amount: > 0 and < $500
     - Passenger count: 0 < count ≤ 6
     - Trip duration: 0 < duration < 180 minutes
     - Average speed: 0 < speed < 100 mph

3. **Feature Engineering**
   - Calculates trip duration (minutes)
   - Computes average speed (mph)
   - Extracts temporal features:
     - `hour_index`: Pickup datetime rounded down to the hour (used as the primary time identifier)
     - `year`, `month`, `day`, `day_of_week`, `hour_of_day`
   - Adds policy status labels:
     - `policy_status`: "pre-policy" or "post-policy" (based on policy date: 2025-01-05)
   - Adds temporal status labels:
     - `weekend_status`: "weekday" or "weekend"
     - `holiday`: Boolean (includes weekends and NYC observed holidays)
   - Maps taxi zones to NTA zones:
     - `PUNTA`: Pickup NTA zone
     - `DONTA`: Dropoff NTA zone

4. **Zone-Based Aggregation**
   - **Key Innovation**: Aggregates by hour and NTA zone (not by trip origin)
   - Creates a comprehensive grid of all hour-NTA combinations
   - Calculates **outflow features** (trips departing from the zone):
     - `outflow_trips`: Number of trips
     - `outflow_total_distance`: Total distance (miles)
     - `outflow_total_passengers`: Total passenger count
     - `outflow_total_duration`: Total duration (minutes)
     - `outflow_avg_speed`: Average speed (mph) = total distance / total duration
   - Calculates **inflow features** (trips arriving at the zone):
     - `inflow_trips`: Number of trips
     - `inflow_total_distance`: Total distance (miles)
     - `inflow_total_passengers`: Total passenger count
     - `inflow_total_duration`: Total duration (minutes)
     - `inflow_avg_speed`: Average speed (mph) = total distance / total duration
   - **Note**: Outflow uses `pickup_hour` (when trip starts), inflow uses `dropoff_hour` (when trip ends)

5. **Weather Data Integration**
   - Merges NTA-level weather data based on `hour_index` and `NTA_zone`
   - Adds weather features:
     - `weather_temperature`: Temperature (°F)
     - `weather_precipitation`: Precipitation (mm)
     - `weather_windspeed`: Wind speed (mph)
     - `weather_humidity`: Relative humidity (%)
   - Handles missing weather data gracefully (fills precipitation with 0, leaves other fields as NaN)

6. **Data Consolidation**
   - Combines aggregated data from all processed months
   - Sorts by `hour_index` and `NTA_zone`
   - Generates comprehensive statistics and summary reports

#### Key Updates and Improvements

1. **Aggregation Paradigm Shift**
   - **Previous**: Aggregated by "trips departing from a zone in an hour"
   - **Current**: Aggregates by "zone in an hour" with both inflow and outflow metrics
   - This provides a complete picture of zone activity, not just departures

2. **Dual Flow Metrics**
   - Each row now contains both inflow and outflow features
   - Enables analysis of zone-level traffic patterns, net flow, and activity balance

3. **NTA-Level Weather Integration**
   - Replaced uniform Central Park weather with zone-specific weather data
   - Weather data matched by `hour_index` (datetime) and `NTA_zone`
   - More accurate spatial representation of weather conditions

4. **Time Identifier Standardization**
   - `hour_index` is now the pickup datetime rounded to the hour (not a separate index)
   - Simplifies time-based analysis and merging operations

5. **Comprehensive Feature Set**
   - Maintains all standard temporal and policy labels
   - Adds zone-level traffic metrics (inflow/outflow)
   - Integrates spatial weather data

#### Output File
- **Location**: `data/nta_zone_hourly_taxi_summary.csv`
- **Format**: CSV with UTF-8-sig encoding
- **Structure**: Each row represents one hour for one NTA zone
- **Key Columns**:
  - Identifiers: `hour_index`, `NTA_zone`
  - Temporal: `year`, `month`, `day`, `day_of_week`, `hour_of_day`
  - Status: `policy_status`, `weekend_status`, `holiday`
  - Weather: `weather_temperature`, `weather_precipitation`, `weather_windspeed`, `weather_humidity`
  - Outflow: `outflow_trips`, `outflow_total_distance`, `outflow_total_passengers`, `outflow_total_duration`, `outflow_avg_speed`
  - Inflow: `inflow_trips`, `inflow_total_distance`, `inflow_total_passengers`, `inflow_total_duration`, `inflow_avg_speed`

#### Benefits

1. **Spatial Accuracy**: Zone-specific weather data improves model accuracy
2. **Comprehensive Analysis**: Inflow/outflow metrics enable traffic flow analysis
3. **Data Alignment**: Weather data format aligns with team standards
4. **Scalability**: Script processes multiple months automatically
5. **Robustness**: Includes comprehensive error handling and data validation
